== Introduction

The CalConnect Standards Registry publishes CalConnect deliverables —
standards, specifications, guides, directives, and other documents —
at https://standards.calconnect.org.

The site is an aggregator: it discovers Metanorma document repositories
via the `metanorma-release` GitHub topic, fetches their published releases,
and builds a static site with full-text search, category pages, and document downloads.

The site is managed by TC PUBLISH.

It also rebuilds daily at 06:00 UTC to pick up new releases from document repos.


== Architecture

=== How documents get published

. **Document repo** — A Metanorma repo (e.g. `cc-icalendar-series`) compiles `.adoc` sources
  and runs the `release` workflow, which publishes ZIP archives to GitHub Releases
  with channel labels (e.g. `public/standards`).
. **Aggregation (producer)** — `metanorma-release aggregate` discovers repos
  by the `metanorma-release` topic, fetches their releases, filters by channel,
  extracts document files, and enriches metadata from Relaton bibliographic data.
. **Enrichment (contract layer)** — `rake enrich` (`lib/registry/`) turns the producer
  outputs into the catalog contract: Relaton is the single source of truth, every
  top-level field is a documented projection, files carry `media_type`/`bytes`/`sha256`
  and stable URLs, items carry provenance, language/license/copyright, a URN in the
  instance namespace, and the per-document editions model. The handoff directory
  `registry/` is renderer-neutral — no Jekyll paths cross it.
. **Rendering** — The Jekyll plugin `_plugins/registry_catalog.rb` reads `registry/`
  and generates the versioned document pages, `latest` aliases, legacy redirects,
  `/catalog.json` (+ `.sha256` checksum sidecar), `/search-index.json`,
  `/feed.xml` (Atom), `/opensearch.xml`, `/sitemap.xml`, per-document
  citation exports (BibTeX/RIS/CSL-JSON) with Google-Scholar `citation_*`
  meta, and the Pagefind full-text index behind `/search/`. Bibliographic
  relations (`updatedBy`, `derivedFrom`, …) project from Relaton and render
  as cross-linked Related-documents sections.
  Vite compiles the JavaScript and Tailwind CSS.
. **Deploy** — GitHub Pages serves the built site.

=== The data contract

The most valuable thing this repository produces is the document catalog:

* `https://standards.calconnect.org/catalog.json` — the full catalog, fetchable
* Schema: `https://schemas.metanorma.org/registry/documents-index/v1.json`
  (see `_data/schemas/documents.schema.json`), payload `version: 1`
* Search corpus: `https://standards.calconnect.org/search-index.json`
* Full-text search index (Pagefind): `https://standards.calconnect.org/pagefind/` + `/search/`
* Feed: `https://standards.calconnect.org/feed.xml` (Atom, RFC 4287)
* Search description: `https://standards.calconnect.org/opensearch.xml`
* Sitemap: `https://standards.calconnect.org/sitemap.xml`
* Catalog checksum: `https://standards.calconnect.org/catalog.json.sha256`
* Per-document citations: `/docs/{slug}.bib`, `/docs/{slug}.ris`, `/docs/{slug}.csl.json`

Stability promise: within schema major version 1, changes are additive only;
consumers must ignore unknown keys. The Relaton record in each item's
`bibliographic` field is canonical; other fields are projections documented
in the schema and verified by `rake validate_consistency` on every build.

**Any generator that emits a payload conforming to the schema is a valid
producer.** The `metanorma-release` gem is one producer — not the definition
of the data. `fixtures/seed/` contains a hand-written producer used by the
conformance suite (`rake conformance`), and `rake validate_index[path]`
validates any candidate catalog against the published schema.

The registry engine — the contract schemas, enrichment, `registry-validate`
and `registry-conformance` CLIs, golden fixtures and a certified non-Jekyll
second renderer — lives in
https://github.com/metanorma/standards-registry[metanorma/standards-registry]
and is consumed here as a gem (see `Gemfile`). This repository keeps only the
instance configuration (`_config.yml` `registry:` map +
`metanorma.aggregate.yml`), the reference Jekyll renderer bridge
(`_plugins/registry_catalog.rb` + layouts), branding and content. The
conformance profile and instance guide are published in the product repo;
schemas are served at their $id paths from the product's Pages
(https://schemas.metanorma.org DNS pending org setup; meanwhile
https://metanorma.github.io/standards-registry/registry/documents-index/v1.json).

== Quick start

[source,sh]
----
# Install dependencies
bundle install
npm ci

# Aggregate + enrich the catalog + build the site
bundle exec rake build

# Serve locally
npx serve _site
----

NOTE: Aggregation requires a `GITHUB_TOKEN` with read access to the CalConnect organization repos.
Set it as an environment variable or in `.env`.


== Build commands

The `Rakefile` provides these tasks:

[cols="1m,3",options="header"]
|===
|Command |Description
|`rake fetch` |Aggregate releases into `_site/docs/` (network)
|`rake enrich` |Build `registry/catalog.json` + `search-index.json` + `backfill.json` from producer outputs (no network)
|`rake build` |Fetch + enrich + compile Vite + build Jekyll site
|`rake jekyll` |Build Vite + Jekyll only (assumes enrich already done)
|`rake serve` |Serve with Jekyll's dev server
|`rake clean` |Remove `_site/` and `registry/`
|`rake validate_schema` |Validate the catalog against the published schema
|`rake validate_consistency` |Recompute Relaton projections; verify files, URLs, editions
|`rake validate_index[path]` |Validate any candidate catalog against the schema (generator independence)
|`rake conformance` |Build the reference renderer against golden fixtures and run the conformance suite
|`rake spec` |Run the RSpec suite
|===


== Configuration

=== `_config.yml` — registry instance configuration

[source,yaml]
----
registry:
  org: calconnect
  urn_namespace: calconnect
  url_scheme: "/docs/:document_id/:year/"
  docs_prefix: "/docs"
  legacy_prefixes: ["cc"]
  features:
    search: true
    atom_feed: true
    jsonld: true
    opensearch: true
    html: true
  license_default: null
----

* `org`, `urn_namespace` — identity used for URNs (`urn:calconnect:cc-18011:2018`)
* `url_scheme` — canonical document URL template (`:document_id`, `:year`, `:edition` tokens)
* `legacy_prefixes` — old artifact prefixes that get redirect stubs (HTML only)
* `features` — toggles for search/feed/JSON-LD/OpenSearch; `html: false` selects headless mode
* `license_default` — fallback license; `null` means absent fields stay null and are
  tracked in `registry/backfill.json` (never invented)

=== `metanorma.aggregate.yml`

Controls how the aggregator discovers repos and builds output:

[source,yaml]
----
source: github
output_dir: _site/docs
file_routing: flat
cache_dir: .cache/aggregate

channels:
  - public

include_drafts: true

display_categories:
  - name: Standards, Specifications & Reports
    slug: standards
    doctypes: [standard, specification, report]
  - name: Guides & Advisories
    slug: guides
    doctypes: [guide, advisory]
  - name: Directives
    slug: directives
    doctypes: [directive]
  - name: Administrative
    slug: administrative
    doctypes: [administrative]
  - name: Amendments & Technical Corrigenda
    slug: amendments
    doctypes: [amendment, technical-corrigendum]

github:
  organizations:
    - CalConnect
  topic: metanorma-release
----

Key settings:

* `output_dir` — where extracted document files are written
* `channels` — which channels to subscribe to (`public` matches all `public/*`)
* `display_categories` — maps doctypes to site categories
* `include_drafts` — include working drafts, committee drafts, etc.

=== Delta state cache

Aggregation is incremental. The `.cache/aggregate/` directory tracks which repos/tags have been processed.
CI caches this directory between builds to avoid re-downloading unchanged releases.

When the output directory is missing (fresh runner), the Rakefile resets the delta
state so artifacts are re-extracted from the cached downloads.


== How to add/remove documents

=== Adding a document

Documents are added by creating a new Metanorma repository:

. Use the https://github.com/CalConnect/cc-template[`cc-template`] repository template
. Add the `metanorma-release` topic to the new repository
. Write the document in AsciiDoc and push to `main`

The document will appear on standards.calconnect.org after:

. The document repo's `release` workflow runs (on push to `main`)
. This site's next build (push to `main` or daily cron)

No changes to this repository are needed.

=== Removing a document

. Archive or delete the document repository, or
. Remove the `metanorma-release` topic from the repository

The document will disappear from the site on the next build.

=== Changing a document's category

Document categories are determined by doctype.
Edit `metanorma.aggregate.yml` → `display_categories` to change which doctypes map to which category.

== CI/CD

The `build_deploy` workflow:

. Sets up Ruby 3.3 + Node.js 24
. Restores aggregate cache (`.cache/aggregate/`)
. Runs `bundle exec rake build` (aggregate + Vite + Jekyll)
. Verifies the build produced >0 documents
. Uploads Pages artifact
. Deploys to GitHub Pages (on `main` only)

Scheduled builds run daily at 06:00 UTC to pick up new releases.
